# AGENTS.md

Стадия «Разработка» контура производства: на входе системные требования, на
выходе проверенный код в пул-реквесте.

## Источник правды — здесь

`poh_developer/*.py` исполняются контуром: `poh-issue-agents` ставит пакет и
импортирует из него, своих копий там больше нет. Правка здесь доезжает до
контура бампом пина в его `worker/requirements.txt`.

Отсюда два следствия. Правка модуля стадии — правка боевого кода, даже когда
выглядит как правка библиотеки. И `poh_developer/runner.py` держит инварианты
образа, с которыми сверяется образ воркера в соседнем репозитории: разъехались
— красный шаг разработки на зелёном коде (прогон #13).

## Agent skills

### Issue tracker

Issue живут в GitHub Issues этого репозитория; в средах без `gh` те же операции
идут через MCP. См. `docs/agents/issue-tracker.md`.

### Triage labels

Канонические роли смаплены на словарь контура, и метки там **исполняемые**:
`ready-for-dev` запускает агента разработки, `agents:off` снимает задачу.
Читайте до простановки любой метки. См. `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `CONTEXT.md` и `docs/adr/` в корне. См. `docs/agents/domain.md`.

## Инварианты, оплаченные прогонами

Каждый — тест. Правка, ломающая любой из них, ломает живой контур.

- **Токена агенту не дают.** В контейнер исполнителя уезжают ровно три
  переменные: `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`. Коммит, пуш и PR
  делает воркер после прогона, своими руками.
- **uid раннера — 10001**, тот же, что в `agent/Dockerfile`. Разъехались числа
  — агент молча пишет в `/tmp` и докладывает об успехе (прогон #19).
- **Мажор Node — 22**, объявлен в `runner.py` и сверяется с образом. Разъезд
  с воркером даёт красный шаг разработки на зелёном коде (прогон #13).
- **Служебный файл — в `SERVICE_FILES`.** Перечень один, снятие одной
  функцией; забытый файл уезжает в пул-реквест и прячет то, что агент кода не
  тронул (прогоны #19, #35).
