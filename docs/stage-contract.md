# Контракт стадии «Разработка»

Что стадия обязана получить, что обязана отдать и чего от неё нельзя требовать.
Всё остальное — реализация и может меняться.

---

## Вход

Стадия начинается в точке передачи **H1** протокола агентов.

| Что | Откуда | Обязательно |
|---|---|---|
| Issue с меткой `ready-for-dev` | стадия «Аналитика» | да |
| `sa_documentation/FNR/FNR_1/system_requirements.md` в ветке аналитики | стадия «Аналитика» | нет¹ |
| `task.md`, `concept.md` рядом с ним | стадия «Аналитика» | нет |
| раздел **HowToDemo** в теле Issue | гейт приёмки | да² |
| `.openhands/task-rules.md` в целевом репозитории | целевой репозиторий | да |
| `AGENTS.md` / `CLAUDE.md` в целевом репозитории | целевой репозиторий | нет |
| `DEVELOP_TEST_COMMAND` — команда проверок | конфигурация контура | да |

¹ Нет требований — стадия работает от тела Issue. Отсутствие передаётся
**пустой строкой**, а не отсутствием ключа: агент обязан отличать «аналитики не
было» от «ветка не найдена».

² HowToDemo — граница MVP. Пока он не проходит, делается только то, что к нему
ведёт. Без него у стадии нет критерия остановки, и она превращается в
бесконечное улучшение.

## Выход

| Исход | Что остаётся | Что видит цикл |
|---|---|---|
| **Успех** | ветка `feature/<N>-openhands`, открытый PR с `Closes #N`, зелёные тесты, находки в секции GROW родителя | `phase: pr-open, status: started` |
| **Своя краснота не починилась** | черновой PR с работой агента | `phase: in-development, status: failed` + причина |
| **Агент не сделал ни одного хода** | ничего | `status: failed` + «отказ окружения, а не работы агента» |
| **Агент отработал, дифф пуст** | ничего | `status: failed` + «вопрос к постановке» |
| **Рубильник `agents:off`** | ничего | **ничего** — это решение человека, а не сбой |
| **Не хватило памяти хоста** | ничего | `status: failed` + порог и переменная |

Последняя строка первой таблицы важнее, чем кажется: **`agents:off` не
докладывается провалом**. Человек забрал задачу себе — докладывать об этом циклу
как о срыве значит врать ему. В режиме `dispatch` под это выделен отдельный job,
а не первый шаг разработки: упавший шаг сделал бы весь прогон `failure`.

## Чего от стадии нельзя требовать

- **Починить то, что было сломано до неё.** Чужая краснота диагностируется и
  публикуется как есть. Расширять ветку чужими поломками — значит потерять
  границу того, что в ней сделано.
- **Исправить найденный по дороге edge-кейс.** Находка идёт в GROW родителя.
  Правило существует, чтобы ветка оставалась про свою задачу.
- **Сойтись с ревью любой ценой.** Потолок — 3 круга. Дальше человек.
- **Отвечать за поведение на проде.** Это `.delivery/checks.json` и
  Delivery-Agent.

## Контракт исполнителя

Сегодня исполнитель один — OpenHands 1.16.0. Но интерфейс, по которому контур
с ним работает, от него не зависит и записан здесь, чтобы смену исполнителя не
пришлось выводить из кода (см. [`gaps.md`](gaps.md), G7).

**Что исполнитель получает:**

```
/workspaces/<слаг задачи>/
├── repo/                 ← рабочий каталог, он же -w контейнера
│   ├── .task.md          ← постановка: требования, Issue, правила репозитория
│   └── … клон целевого репозитория на ветке feature/<N>-…
└── .openhands/
    └── mcp.json          ← доступ к Repowise; HOME переставлен сюда
```

Переменные окружения — **ровно три**: `LLM_API_KEY`, `LLM_BASE_URL`,
`LLM_MODEL`. Токена GitHub нет и не будет.

**Что исполнитель отдаёт:**

| Файл / состояние | Смысл | Кто читает |
|---|---|---|
| изменённое рабочее дерево | сама правка | воркер: коммит и пуш |
| `.followups.md` | находки для бэклога, заголовок `## …` на находку, ≤8 | `collect_dev_followups` → GROW |
| `.reflect.md` | намерения для слоя саморефлексии | запись об итерации, **после** публикации |
| `.openhands/conversations/*/events/` | сделал ли ход хоть один | `develop.agent_moved` |

**Требования к контейнеру исполнителя:**

- одноразовый (`--rm`), детерминированное имя (слаг задачи) — чтобы остаток
  можно было найти и снять;
- непривилегированный пользователь с **uid 10001** — каталог задачи готовит
  воркер от root и передаёт ему `chown`. Разъехались числа — агент молча уходит
  писать в `/tmp` и докладывает об успехе (прогон #19: потеряна 21 минута, PR
  открылся пустым);
- мажор Node тот же, что у воркера: код проекта исполняет раннер, а проверки
  проекта гоняет воркер (прогон #13: Node 20 против 22, glob не раскрылся,
  красный шаг разработки на зелёном коде);
- потолок прогона — 45 минут. Больше часа это не «агент думает», это агент
  застрял.

## Служебные файлы

Всё, что контур и агент создают в клоне ради самого прогона и что **не** является
частью правки:

| Файл | Кто пишет | Снимается перед коммитом |
|---|---|---|
| `.task.md` | контур | да |
| `.followups.md` | агент | да, **после** переноса находок |
| `.verdict.md` | контур (круг правок) | да |
| `.reflect.md` | агент | да, но **сохраняется** рядом — его читают после публикации |
| `.harness/` | контур | **нет — коммитится намеренно** |

`.harness/` не в перечне сознательно. Остальные файлы — вход контура для одного
прогона: постановка пересказана в лог, находки перенесены, разбор ревью — в
комментарий PR, и после этого их смысл исчерпан, а в коммите они шум. `.harness/`
наоборот — это **задача в файлах**: он коммитится вместе с кодом, чтобы было
видно в PR и читалось через полгода.

Добавляешь служебный файл — добавляй в `SERVICE_FILES`. Механизм уже отказывал
дважды и оба раза молча: прогон #19 (постановка на 1721 строку уехала в PR и
скрыла, что кода агент не тронул) и прогон #35 (оба круга правок закоммитили
собственную постановку — `.verdict.md` снимался, `.task.md` забыли).

## Точки передачи

| Точка | Между кем | Признак перехода |
|---|---|---|
| **H1** | Аналитика → Разработка | метка `ready-for-dev` + системные требования |
| **H2** | Разработка → Ревью | PR открыт, `Closes #N` в теле |
| **H3** | Ревью → Доводка | ревью опубликовано, доклад `pr-review` |
| **H4** | Доводка → Человек либо мерж | пустой дифф (сошлось) либо потолок кругов (`needs-human:pr`) |
| **H5** | Мерж → Отгрузка | `.delivery/checks.json`, очередь Delivery-Agent |

Сквозной ключ всей цепочки — **`Closes #N`** в теле PR. По нему Issue-Agent и
PR-Agent собирают один таймлайн из двух сервисов, а GitHub закрывает задачу при
слиянии. Несколько `Closes #N` в одном теле оставляют ключ **пустым намеренно**:
выбрать первый попавшийся значит привязать работу не к той задаче.
