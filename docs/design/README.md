# Проектный след стадии

Замыслы и планы, по которым стадия «Разработка» построена. Скопированы из
`poh-issue-agents/docs/superpowers/` на срезе `3e9040ce` — там они лежали
вперемешку с документами аналитики, триажа и оценки, и найти по ним историю
одной стадии было нечем.

Читаются парами: `*-design.md` — замысел и обоснование, одноимённый файл без
суффикса — план реализации по задачам.

| Документ | О чём | Состояние кода |
|---|---|---|
| `2026-08-19-fnr6-develop-as-child-workflow.md` | разработка становится дочерним воркфлоу, а не активностью: свой WorkflowId, своя политика ретраев на каждый шаг | **реализовано** |
| `2026-09-02-dev-partial-publish*.md` | сорванный прогон оставляет черновой PR с работой агента вместо пустоты | **реализовано** |
| `2026-09-02-dev-repair-loop*.md` | прогон отличает свою поломку от чужой и от мигающего теста, чинит свою одним заходом | **реализовано** |
| `2026-09-03-human-review-reaches-contour*.md` | формальное ревью человека и построчное замечание будят круг правок так же, как доклад PR-Agent | **реализовано** — `shared/review_events.py`, `github_client.changes_requested`; пометка «замысел к валидации» в шапке спеки отстала от кода |
| `2026-09-03-pr-review-own-repo-design.md` | ревью PR в собственном репозитории контура | **не принято к реализации** |

## Зачем это здесь

В этих документах записаны не решения, а **их причины** — и почти каждая
причина оплачена живым прогоном:

- прогон #39: одна активность на четыре шага повторялась целиком, `git push`
  падал уже после работы агента, и контур трижды объявлял о передаче задачи;
- PR #172 (3 сентября): контур дважды прогнал круг правок по автоматическому
  ревью и заключил «PR готов к слиянию», пока формальное ревью человека стояло
  в `CHANGES_REQUESTED` с замечанием про регрессию;
- PR #305/#306 (4 сентября): первая редакция спеки о ревью в своём репозитории
  утверждала, что ревью не запускается, — и была опровергнута фактом, из-за
  чего появилась вторая редакция.

Такие разборы не воспроизводятся рассуждением. Терять их вместе с папкой
чужого репозитория дороже, чем держать копию.
