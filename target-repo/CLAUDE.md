# CLAUDE.md

Гайд для Claude Code в этом репозитории. Он же демо-стенд контура производства —
здесь ходят Issue-Agent, OpenHands и PR-Agent, поэтому конвенции жёстче обычного:
на них держится автоматика.

## Git-workflow (обязательно)

**Правило:** любая доработка ведётся через Issue. Цель — прозрачная хронология:
любой агент восстанавливает контекст, читая один Issue, без раскопок в чате.

1. **Issue первым делом.** Запрос на доработку → перед любым кодом заводится
   Issue. Без Issue работа не начинается.
2. **HowToDemo в Issue.** Конкретный сценарий, которым проверяется готовность:
   что запустить, что сделать, что должно получиться. Это граница MVP. Нет
   HowToDemo — нет критерия «готово».
3. **Ветка = Issue.** `feature/<номер>-<slug>` либо `fix/<номер>-<slug>`.
4. **PR = Issue.** `Closes #<номер>` в теле.
5. **Хронология непрерывна.** Значимый шаг — комментарий в Issue.

## MVP первым, edge-кейсы — в SubIssue (обязательно)

Найденный по дороге edge-кейс **не берётся в работу сразу** — он выносится
SubIssue с `root-issue: #N` и меткой `origin:agent`. К нему возвращаются после
того, как MVP прошёл HowToDemo.

Агент разработки заводит их не сам: он пишет находки в `.followups.md` в корне
рабочего каталога (раздел `## <кратко>` на находку), а SubIssue по ним создаёт
контур своим токеном. Токена у агента нет намеренно — он исполняет код
репозитория.

Единственное исключение — edge-кейс, без которого HowToDemo не проходит. Тогда
это часть MVP, и надо явно сказать, чем именно он ломает демо.

**DON'T:** чинить edge-кейс «раз уж он рядом»; расширять scope ветки находками,
не блокирующими HowToDemo; держать находки только в чате — не зафиксированные
SubIssue теряются.

## Метки контура

Их пишет автоматика, и правило простое: **одна метка — один писатель**.

| Метка | Пишет | Смысл |
|---|---|---|
| `advisor:*`, `priority:*`, `phase:*` | Issue-Agent | классификация, приоритет, фаза задачи |
| `research-me`, `build-me` | человек | запуск дорогой стадии |
| `ready-for-dev` | Issue-Agent | задача подготовлена, можно брать в работу |
| `origin:agent` | любой агент | артефакт создан агентом, а не человеком |
| `agents:off` | человек | рубильник: агенты не трогают этот Issue |

Чужую метку агент только читает.

## Проверки

```bash
node --test "tests/*.test.mjs"
```

Новая логика — новый тест. Расчёт здесь единственное, что может сломаться молча.

## Границы кода

- Арифметика — в `src/pricing.mjs`, чистыми функциями. `src/server.mjs` только
  разбирает запрос и отдаёт коды: логика в обёртке — логика, которую тест не
  увидит.
- Зависимостей у сервиса нет. Новая заводится, только если задачу нечем закрыть
  из стандартной библиотеки, и причина пишется рядом с кодом.
